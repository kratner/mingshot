# M1: capture done properly + metadata (in progress)

PLAN.md §6, tracked in kratner/planning#30.

## Done

### Window and full-display modes (2026-11-26)

- **Mode picker** in the capture window: Region, Window, Full display, plus **Shadow** (window mode). ⌃⇧2 uses the
  same mode. The choices are remembered between launches.
- **Window:** when New is clicked, MingShot reads the windows on screen, front to back (`windows::on_screen`: app
  windows, panels, menus and pop-ups; not the desktop, menu bar, Dock or MingShot). The overlay highlights the
  window under the pointer with its app and title; a click takes it.
- **Full display:** the overlay highlights the display under the pointer; a click takes the whole frozen frame.
- **In every mode a drag still makes a region** (as in Snagit); a press that moves less than 4 pt is a click.
- **Window capture** is macOS 26's `SCScreenshotManager captureScreenshotWithFilter` with a single-window filter and
  `ignoreShadows`. That's the window on its own, covered parts included, transparent around it, and exactly the
  Mac's own window screenshot (`screencapture -l`, `-o -l` without the shadow), alpha included.
  - Tried first: `captureImageWithFilter`. Without the shadow it matches, but it can't size the shadow: the output
    has to be bigger than the window, and the shadow's real extent (23 pt left and right, 16 up, 30 down on an
    inactive window; more on the active one) isn't reported. Making the output bigger and trimming to the visible
    shadow came out 2-4 px smaller than the Mac's, which keeps a fully transparent fringe.
  - That call is macOS 26+; older systems use CoreGraphics' `CGWindowListCreateImage` (below).
- ⌃⇧2 sometimes arrived twice per press; a repeat within 300 ms is ignored.

### Back to macOS 10.14 Mojave (2026-11-26, PLAN.md §7.9)

- **Universal app** (Apple silicon and Intel), Intel minimum 10.14, Apple silicon 11.0. `npm run app` builds it
  into `build/MingShot.app`.
- **Capture by macOS version** (`compat.rs`):

  | | macOS 26+ | 15.2 – 25 | 10.14 – 15.1 |
  |---|---|---|---|
  | Display | ScreenCaptureKit `captureImageInRect` | same | `CGDisplayCreateImage` |
  | Window | ScreenCaptureKit `captureScreenshotWithFilter` | `CGWindowListCreateImage` | same |
  | Screen Recording permission | yes | yes | from 10.15; Mojave has none |

  The CoreGraphics calls are missing from the newest SDKs' headers but still present and working on macOS 27, so
  they're looked up by name at run time. ScreenCaptureKit is weak-linked, and every other imported symbol existed by
  macOS 10.13 (checked with `nm -u`).
- **On the older path the overlay waits for the displays to be read** (it can't yet be shown to stay out of a
  CoreGraphics capture), and MingShot waits 50 ms after hiding its window before reading.
- **Frontend for Safari 12** (Mojave's original WebKit): mouse events instead of pointer events, margins instead of
  flex `gap`, no `inset`; the bundle targets Safari 12 and a script failure shows a message instead of a blank window.
- **Checked here with `MINGSHOT_LEGACY=1`** (forces the older path on this Mac): displays and regions pixel-exact
  against `screencapture -D`; windows exact against `screencapture -l` except windows with macOS 26's glass title
  bars and sidebars, which the old call can't draw (that glass doesn't exist on the systems that use it).
- **Checked on a real Mojave Mac (Keith, 2026-11-26):** Region, Window and Display captures with and without shadow
  all work; Esc cancels. The first build's Mode and Delay dropdowns didn't open there (a native `<select>` pop-up
  in Mojave's WebKit: the panel flashed white), so they're rows of buttons now. **When more options need a
  dropdown, build one in the page, never a native `<select>`.** Still worth a run on macOS 12–15.

### Magnifier, nudge and Shift lock (2026-11-26)

- **Magnifier** beside the pointer: the frozen frame's 15×15 device pixels around it, 8× with a grid and the centre
  pixel outlined in gold, and under it the pointer's position in device pixels and the centre pixel's colour; while
  dragging, the selection's size in pixels. Rust copies a display's pixels once on the magnifier's first look and
  sends a 900-byte patch per frame drawn (`loupe` command, binary response). It flips to stay on the display.
- **Arrow keys while dragging** move the dragged corner one device pixel (Option: ten). **Shift while dragging**
  locks the proportions the selection has at that moment (square if it's still a point); let go to unlock.
- Geometry in `src/geometry.ts`, unit-tested by `npm run test:ui` (Node strips the types).
- **Checked by hand (Keith, 2026-11-26):** the magnifier follows with position and colour; arrows move 1 px and
  Option+arrows 10 px; Shift locks the proportions. His note: the colour ran into the y value ("490#5B3577"), so
  the readout is now two labelled lines (`x 1698  y 490`, then a swatch and `#5B3577`; size and position while
  dragging).

### Cues per mode (Keith, 2026-11-26)

The magnifier and crosshair are for placing edges, so they show in Region mode and, in the other modes, only once a
drag starts (a drag still makes a region). Window mode: a tag on the highlighted window's top-left corner with the
app (gold), the title and the size in pixels. Display mode: a card in the middle with the size and "Click to capture
· drag for a region · Esc cancels".

### Repeat last region (2026-11-26)

- **Repeat** button beside New, and **⌃⇧3**: the last dragged region again (same display, same rectangle in
  points), straight to the clipboard with no overlay. Disabled until a region has been dragged; the region is
  remembered between launches. If its display isn't attached, it says so.
- End to end: `npm run e2e` (region) ends with ⌃⇧3 and checks the copy against the screen.

### After capture: copy, save, both (2026-11-26)

- **After capture** setting (Copy / Save / Both, remembered; Copy is the default). Save writes a PNG to
  **~/Pictures/MingShot** (Keith) named like the Mac's screenshots, `MingShot 2026-11-26 at 17.42.05.png`, with
  `(2)`, `(3)`… when a name is taken (`output.rs`, unit-tested).
- The status line says where the capture went and offers what's left: **Copy**, **Save**, **Show in Finder**,
  **Open** (in the default image app, saving first, until the editor arrives in M2).
- End to end: a `save` run checks the file against the screen and that the clipboard wasn't touched, then deletes
  the file it made.

### Focus waits for the capture (2026-11-26)

The display e2e run caught other apps' windows drawn inactive in a capture: MingShot activated itself (for Esc and
the arrow keys) right after asking for the frames, and on a slow frame the switch landed first, greying title bars
and swapping the menu bar. The overlay still goes up at once, but MingShot now takes focus only once every display
has been read (`overlay::focus`), so a capture shows the screen as it was when New or ⌃⇧2 was pressed. Esc works
from then (100–200 ms in). The e2e display check skips MingShot's own capture window (meant to be absent), and a
few pixels in one small spot (a spinner caught mid-cycle) pass with a note.

### Metadata (2026-11-26)

- Recorded with every capture (`metadata.rs`): local time with offset; kind (region / window / display); the
  display (id, scale, pixel size); the area in points and pixels; and the **source window**: the window captured,
  the frontmost window under a region's centre, or a display's frontmost window. Its app, bundle id and title come
  from the window list taken when New was pressed.
- **Web address and document path** come from Accessibility (the window's `AXDocument`, else a browser's web area
  `AXURL`), at most ⅓ s per app, after the picture is already on the clipboard or saved. **Opt-in**: without the
  permission they're empty and the capture window offers "Add web addresses and file paths…", which shows macOS's
  prompt only when clicked.
- **Sidecar:** a saved PNG gets `<same name>.mingshot` beside it (`format`, `version`, `image`, `metadata`,
  `annotations: []` for M2). The clipboard stays image only (PLAN.md §7.8). The status line shows the source:
  "from Chrome · Pull requests · https://…".
- Checked on this Mac (`cargo run --example metadata_probe`): Chrome windows give their page addresses; bundle ids
  and titles right everywhere; most lookups 0–60 ms. Not found: Vivaldi's address (Chromium builds its
  accessibility tree only when asked: setting `AXManualAccessibility` would fix it) and Finder folders.
- **Every window in the capture (Keith, 2026-11-26):** the capture's area is sampled on a grid of up to 96×96
  points; at each point the frontmost window is the one that shows, so a window hidden behind others inside the
  capture isn't listed. Each visible window is recorded with its share (`coverage`), frame, app, bundle id, title
  and page or file, most first; `source` is the first. Lookups run in parallel (up to 16 windows). A display
  capture lists every window on the display; a window capture just that window. The status line says "from X …
  and N more windows", with the list and shares on hover. Electron apps' own pages (inside the app bundle) aren't
  taken for documents.
- Display names aren't recorded yet (NSScreen's name is 10.15+ and main-thread only).
