# M1: capture done properly + metadata (in progress)

PLAN.md §6, tracked in kratner/planning#30.

## Done

### Window and full-display modes (2026-11-26)

- **Mode picker** in the capture window: Region, Window, Full display, plus **Shadow** (window mode). ⌃⇧2 uses the
  same mode. The choices are remembered between launches.
- **Window:** when New is clicked, MingShot reads the windows on screen, front to back (`windows::on_screen`: app
  windows, panels, menus and pop-ups; not the desktop, menu bar, Dock or MingShot). The overlay highlights the
  window under the pointer with its app and title; a click takes it.
- **Full display:** the overlay highlights the display under the pointer; a click takes the whole frozen frame.
- **In every mode a drag still makes a region** (as in Snagit); a press that moves less than 4 pt is a click.
- **Window capture** is macOS 26's `SCScreenshotManager captureScreenshotWithFilter` with a single-window filter and
  `ignoreShadows`. That's the window on its own, covered parts included, transparent around it, and exactly the
  Mac's own window screenshot (`screencapture -l`, `-o -l` without the shadow), alpha included.
  - Tried first: `captureImageWithFilter`. Without the shadow it matches, but it can't size the shadow: the output
    has to be bigger than the window, and the shadow's real extent (23 pt left and right, 16 up, 30 down on an
    inactive window; more on the active one) isn't reported. Making the output bigger and trimming to the visible
    shadow came out 2-4 px smaller than the Mac's, which keeps a fully transparent fringe.
  - That call is macOS 26+; older systems use CoreGraphics' `CGWindowListCreateImage` (below).
- ⌃⇧2 sometimes arrived twice per press; a repeat within 300 ms is ignored.

### Back to macOS 10.14 Mojave (2026-11-26, PLAN.md §7.9)

- **Universal app** (Apple silicon and Intel), Intel minimum 10.14, Apple silicon 11.0. `npm run app` builds it
  into `build/MingShot.app`.
- **Capture by macOS version** (`compat.rs`):

  | | macOS 26+ | 15.2 – 25 | 10.14 – 15.1 |
  |---|---|---|---|
  | Display | ScreenCaptureKit `captureImageInRect` | same | `CGDisplayCreateImage` |
  | Window | ScreenCaptureKit `captureScreenshotWithFilter` | `CGWindowListCreateImage` | same |
  | Screen Recording permission | yes | yes | from 10.15; Mojave has none |

  The CoreGraphics calls are missing from the newest SDKs' headers but still present and working on macOS 27, so
  they're looked up by name at run time. ScreenCaptureKit is weak-linked, and every other imported symbol existed by
  macOS 10.13 (checked with `nm -u`).
- **On the older path the overlay waits for the displays to be read** (it can't yet be shown to stay out of a
  CoreGraphics capture), and MingShot waits 50 ms after hiding its window before reading.
- **Frontend for Safari 12** (Mojave's original WebKit): mouse events instead of pointer events, margins instead of
  flex `gap`, no `inset`; the bundle targets Safari 12 and a script failure shows a message instead of a blank window.
- **Checked here with `MINGSHOT_LEGACY=1`** (forces the older path on this Mac): displays and regions pixel-exact
  against `screencapture -D`; windows exact against `screencapture -l` except windows with macOS 26's glass title
  bars and sidebars, which the old call can't draw (that glass doesn't exist on the systems that use it).
- **Checked on a real Mojave Mac (Keith, 2026-11-26):** Region, Window and Display captures with and without shadow
  all work; Esc cancels. The first build's Mode and Delay dropdowns didn't open there (a native `<select>` pop-up
  in Mojave's WebKit: the panel flashed white), so they're rows of buttons now. **When more options need a
  dropdown, build one in the page, never a native `<select>`.** Still worth a run on macOS 12–15.
